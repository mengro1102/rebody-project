## B. 키를 확보한 뒤 (1~2시간) — D4 백엔드 배포

순서대로. 각 명령은 `rebody/` 디렉터리에서 실행합니다.

```bash
# B-1. Supabase CLI 초기화 — config.toml 이 없어 이게 없으면 다음 단계가 실패합니다
supabase init

# B-2. 환경변수
cp .env.example .env          # EXPO_PUBLIC_SUPABASE_URL / ANON_KEY 입력
# supabase/.env.local 을 새로 만들어 GEMINI_API_KEY / MFDS_SERVICE_KEY / FCM_* 입력

# B-3. 연결 및 스키마 적용 (마이그레이션 8개)
supabase link --project-ref <ref>
supabase db push

# B-4. Vault 시크릿 (cron이 Edge Function을 호출하는 데 필요)
#   Supabase SQL Editor에서:
#   select vault.create_secret('<ref>.supabase.co', 'project_host');
#   select vault.create_secret('<service-role-key>', 'service_role_key');

# B-5. 시크릿 등록 및 함수 배포 (7개)
supabase secrets set --env-file supabase/.env.local
supabase functions deploy
```

### B-6. MFDS 실호출 검증 — **가장 조용히 크게 틀릴 수 있는 지점**

```bash
MFDS_SERVICE_KEY=<재발급 키> npx tsx scripts/probe-mfds.ts 김치찌개
```

12개 필드를 `OK`/`MISS`로 자동 판정합니다.

- **전부 `OK`** → 넘어가세요
- **`MISS`가 하나라도 있으면** → 그 출력을 저에게 주세요. `FIELD_MAPS`를 맞추겠습니다

> 매핑이 어긋나면 **에러 없이 0kcal이 저장**됩니다. "동작하는 것 같은데 값이 다 0"이
> 이 프로젝트에서 가장 잡기 어려운 상태입니다.

### B-7. RLS 실측 — 코드 리뷰로 대체하지 마세요
